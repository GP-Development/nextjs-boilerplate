# Feature tests

Every test lives at a page (`/tests/<feature>`) or an endpoint (`/api/tests/<feature>`), reports a
timestamp, a render-mode marker and extra facts (`data-testid` elements or JSON), and is judged by the
runner (`scripts/run-compat-tests.ts`). Test ids below are what `--only <id>` and `--expect-fail <id>` take.

**Status meanings:** `PASS` behaves exactly as expected · `PARTIAL` works but degraded (the reason says how) ·
`FAIL` wrong behavior · `SKIPPED` not applicable or not enabled (the reason says why).

**Applies to:** `server` = any Node server host (managed platform, `next start`, Docker/VPS) · `export` = static export
(`npm run test:export`) · `variant` = needs the separate `variants/cache-components` app.

## Static export (`output: "export"`): what is expected

`npm run test:export` builds a temporary copy of the project **without** everything that needs a server, serves
`out/` with a tiny local file server, and runs the suite with `--mode export`.

| Test                                                                                                                                                        | Result in export mode | Why                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| static, font                                                                                                                                                | PASS                  | Plain static output                                                                                                                                                                                                          |
| isr                                                                                                                                                         | PARTIAL               | The page exists but is frozen at build time; no server to revalidate                                                                                                                                                         |
| dynamic-routes                                                                                                                                              | PARTIAL               | Prebuilt paths and 404 work; `gamma` (generated on demand) cannot exist without a server                                                                                                                                     |
| image                                                                                                                                                       | PARTIAL               | The image optimizer is a server feature; export requires `images.unoptimized`                                                                                                                                                |
| error-pages                                                                                                                                                 | PARTIAL               | A 404 page is exported; a page that throws per request cannot be                                                                                                                                                             |
| dynamic, revalidate, streaming, fetch-cache, node-route, edge-route, server-action, proxy, cookies, long-running, body-size, config-rules, env, diagnostics | SKIPPED               | Route handlers, per-request rendering, Server Actions, proxy and `next.config` redirects/rewrites/headers all require a server (Next.js lists them as unsupported)                                                           |
| security-headers                                                                                                                                            | **FAIL (expected)**   | A static file host sets its own headers; `next.config` headers are not applied. Configure them at the host/CDN. `test:export` passes `--expect-fail security-headers` so the script exits 0, but the report still shows FAIL |
